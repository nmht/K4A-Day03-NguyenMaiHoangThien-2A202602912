Trợ Lý Thông Minh Chuỗi Cung Ứng & Kho Vận (Supply Chain Agent)

Giải quyết bài toán tra cứu vị trí lưu kho theo thời gian thực, tự động cập nhật trạng thái đơn hàng trên hệ thống WMS và hỗ trợ tư vấn học vụ VinUni với độ chính xác 100%, không ảo giác.

Tại sao chọn đề tài Kho Vận & Chuỗi Cung Ứng?

  • Tính biến động cao: Trạng thái đơn hàng (Đang chờ xuất kho, Đang vận chuyển, Đã giao) thay đổi liên tục theo thời gian thực.
  • Yêu cầu đọc/ghi 2 chiều (Read/Write): Agent không chỉ trả lời câu hỏi mà còn phải tự thực thi hành động cập nhật DB qua API.
  • Tổ chức dữ liệu chuẩn MCP: Phân tách hoàn toàn giữa bộ não suy luận (Agent) và giao thức dữ liệu (MCP Server).

Tầm quan trọng của ReAct Pattern

Nếu sử dụng Chatbot thông thường (Cấp 2), AI chỉ trả lời dựa vào tri thức đóng băng trong Prompt và sẽ bịa đặt vị trí kho. ReAct Pattern (Cấp 3) giải quyết triệt để vấn đề này:

🧠 Thought (Suy luận)
🛠️ Action (Gọi MCP)
👁️ Observation (Nhận DB)
🏁 Final Answer

4 Tiêu Chí Phù Hợp Của ReAct Agent (Agent Fit Matrix)

Đánh giá chi tiết lý do tại sao ReAct Pattern là kiến trúc bắt buộc cho đề tài này

Tiêu chí 1

Dynamic Decision

Luồng Quyết Định Động

Người dùng có thể hỏi bất kỳ: tra cứu, cập nhật đơn, đặt lịch hẹn hay hỏi quy chế. ReAct Agent tự phân tích Intent để chọn Tool hoặc trả lời trực tiếp mà không cần hardcode rule `if-else` cố định.

Tiêu chí 2

Multi-Step Reasoning

Suy Luận Nhiều Bước

Xử lý tác vụ phức tạp (TC04): Tra cứu vị trí đơn trước ➔ Kiểm tra xem có ở Kho Tổng hay không ➔ Thực hiện lệnh cập nhật trạng thái tương ứng qua chuỗi Thought-Action lặp lại.

Tiêu chí 3

MCP Tool Integration

Tích Hợp Công Cụ MCP

Kết nối an toàn với cơ sở dữ liệu kho vận WMS và hệ thống học vụ VinUni thông qua chuẩn Model Context Protocol (JSON-RPC), bảo đảm dữ liệu chính xác 100%.

Tiêu chí 4

Feedback Loop

Vòng Lặp Phản Hồi Xử Lý Lỗi

Khi MCP Server trả về kết quả ngoại lệ (ví dụ `NOT_FOUND` ở TC05 khi tra cứu đơn `DH9999999`), Agent đọc được Observation để tự điều chỉnh phản hồi lịch sự, trung thực.

Danh Sách Công Cụ Tích Hợp Via MCP Server

Các hàm xử lý nghiệp vụ kho vận và học vụ được phơi duyệt cho Agent gọi

Tool Kho Vận 1

`order_tracking`

Input: order_id (string)

Công dụng: Tra cứu vị trí lưu kho hiện tại, trạng thái đơn hàng, thông tin người nhận, số lượng sản phẩm và lịch sử di chuyển đơn hàng.

// Sample JSON Arguments: { "order_id": "DH2026001" } // Sample Observation Response: { "status": "SUCCESS", "data": { "order_id": "DH2026001", "location": "Kho Hàng A - Q7, TP.HCM", "status": "Đang chờ xuất kho" } }
Tool Kho Vận 2

`order_status_update`

Input: order_id, new_status

Công dụng: Cập nhật trạng thái mới cho vận đơn trong cơ sở dữ liệu WMS và ghi nhận thông báo chuyển trạng thái.

// Sample JSON Arguments: { "order_id": "DH2026001", "new_status": "Đã giao thành công" } // Sample Observation Response: { "status": "SUCCESS", "old_status": "Đang chờ xuất kho", "new_status": "Đã giao thành công" }
Tool Học Vụ 1

`academic_query`

Input: student_id (string)

Công dụng: Tra cứu điểm tích lũy GPA, lớp học, email và Cố vấn học tập được phân công của sinh viên Đại học VinUni.

// Sample JSON Arguments: { "student_id": "SV2026001" } // Sample Observation Response: { "status": "SUCCESS", "data": { "full_name": "Nguyễn Văn An", "gpa": 3.85, "class": "AI-K4" } }
Tool Học Vụ 2

`academic_advisor_booking`

Input: student_id, date, time

Công dụng: Đặt lịch hẹn cố vấn học tập cho sinh viên với Cố vấn phụ trách theo khung giờ mong muốn.

// Sample JSON Arguments: { "student_id": "SV2026001", "date": "2026-09-15", "time": "14:00" }
